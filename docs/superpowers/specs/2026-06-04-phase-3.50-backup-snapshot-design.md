# Phase 3.50 (v1) — Encrypted DB backup + restore + rotation

**Status:** approved (Approach A; decisions delegated, "must work when done")
**Date:** 2026-06-04
**Depends on:** Phase 3.38 (`secret_at_rest` envelope + key at `spear/config/secret.key`)

## Problem

TAPhish has no backup mechanic. A dropped table, a botched migration, or a host
incident loses every engagement's campaigns, recipients, captures, and audit trail.
The production host is **Hostpoint Shared** — no SSH, no `mysqldump`, PHP ~256–512 MB
RAM, all DB access via mysqli, cron via the host "Tasks" panel running a PHP CLI.

## Goal

A CLI that produces a single **encrypted, restorable** backup of the whole database,
prunes old backups, and works at any DB size within shared-hosting memory limits.
Plus a restore CLI so the backup is provably usable (a backup you can't restore is
worthless).

## Scope (v1, locked)

- **In:** full logical DB dump (all `tb_*` tables, schema + data) → gzip → chunked
  AES-256-GCM → rotation (keep last N) → restore/decrypt CLI. CLI-only, local storage.
- **Deferred (structured for later):** state-dir snapshot (cloned sites / uploads),
  off-host push (S3/WebDAV), any web/Settings UI surface.

## Non-goals (YAGNI)

- No `mysqldump` / shell-out (unavailable on the host).
- No web download of backups (re-exposure risk; CLI only).
- No incremental/differential backups — full logical dump each run.
- No multi-row `INSERT` packing — one `INSERT` per row (simplest, correct; gzip
  collapses the repetition).

## Architecture

Two pure helper files (the testable core) + two thin CLI drivers + a generated
`.htaccess`. Nothing touches existing read/write paths.

| File | Responsibility | Tested |
|---|---|---|
| `spear/manager/backup_helper.php` (create) | Pure: SQL serialization (table header + per-row INSERT, injected escaper), backup filename builder, rotation planner. No mysqli. | Unit, offline |
| `spear/manager/backup_archive.php` (create) | Pure: chunked encrypt/decrypt **streaming** framing over injected reader/writer/crypto closures. The memory-bounding core. | Unit, offline |
| `spear/manager/cli/backup_run.php` (create) | Driver: connect, key gate, ensure dir + `.htaccess`, stream-dump all tables → temp `.sql` → gzip → encrypt-stream → atomic rename into place, rotate, audit. | Lint + integration harness |
| `spear/manager/cli/backup_restore.php` (create) | Driver: decrypt-stream a `.tapbak` → gunzip → write `.sql` (default), or `--apply --yes` to execute against the DB. | Lint + integration harness |
| `tests/BackupHelperTest.php`, `tests/BackupArchiveTest.php` (create) | Unit tests with fixed key + in-memory streams. | — |
| `tests/Support/helpers_shim.php` (modify) | Register both pure files. | — |

### Boundaries

- `backup_helper` knows SQL text + filenames + which old files to prune. No crypto,
  no mysqli, no filesystem.
- `backup_archive` knows the on-disk container format and chunking. No SQL, no
  mysqli — it moves bytes through injected reader/writer/crypto closures.
- The CLIs own mysqli, temp files, and wiring the real `secret_at_rest_*` envelope.

## The `.tapbak` container format

```
magic:  "TAPBAK1\n"                         (8 bytes, version-tagged)
frames: repeated, until EOF:
        [4-byte big-endian uint32 frameLen][frameLen bytes = one enc1: envelope]
```

Each frame is the existing, already-tested `secret_at_rest_encrypt()` output (an
`enc1:<base64(iv+tag+ct)>` string) for **one ≤1 MiB plaintext chunk** of the gzipped
SQL. Reusing the tested envelope per frame means no new crypto primitive. Decryption
reads magic, then length-prefixed frames, decrypting each. Memory is bounded by one
chunk (~1 MiB plain + its envelope), regardless of total DB size — this is what makes
it safe on shared hosting.

Base64 inflates each frame ~33%; acceptable for a backup, and the gzip beforehand
more than compensates.

## Component contracts

### `backup_helper.php`

```php
// One table's schema preamble. $createSql is the raw "SHOW CREATE TABLE" body.
function taphish_backup_sql_table_header(string $table, string $createSql): string
// => "DROP TABLE IF EXISTS `t`;\n{$createSql};\n"

// One INSERT for one row. $escape is fn(string):string (real: $conn->real_escape_string).
// NULL values emit literal NULL; everything else is single-quoted + escaped.
function taphish_backup_sql_insert(string $table, array $columns, array $row, callable $escape): string
// => "INSERT INTO `t` (`c1`,`c2`) VALUES ('a','b');\n"

// Stream a whole table through a writer closure (header once, then one INSERT per row).
// $rows is iterable of associative arrays; $write is fn(string):void.
function taphish_backup_dump_table(string $table, string $createSql, array $columns,
                                   iterable $rows, callable $escape, callable $write): int
// returns row count written

// UTC stamp "YYYYmmdd-HHMMSS" (passed in — no Date::now in pure code) -> filename.
function taphish_backup_filename(string $stamp): string
// => "taphish-backup-{$stamp}.tapbak"

// Given existing .tapbak filenames and keep-N, return the ones to DELETE (oldest first).
// Sort is lexical on the embedded timestamp (the filename format sorts chronologically).
function taphish_backup_rotation_plan(array $filenames, int $keep): array
```

### `backup_archive.php`

```php
const TAPHISH_BACKUP_MAGIC = "TAPBAK1\n";
const TAPHISH_BACKUP_CHUNK  = 1048576; // 1 MiB plaintext per frame

// Encrypt a stream. $read()=>string returns next plaintext chunk or '' at EOF.
// $write(string) appends container bytes. $encFn(string $plain):?string = secret_at_rest_encrypt(...,$key).
// Writes the magic header, then a length-prefixed frame per chunk. Throws/returns false
// if any chunk fails to encrypt (so we never emit a partial/uncencrypted container).
function taphish_backup_encrypt_stream(callable $read, callable $write, callable $encFn, int $chunk = TAPHISH_BACKUP_CHUNK): bool

// Decrypt a stream. $read($n)=>string returns up to $n bytes (for header + frames).
// $write(string) appends recovered plaintext. $decFn(string $env):?string = secret_at_rest_decrypt(...,$key).
// Returns false on bad magic, truncated frame, or any decrypt failure (wrong key / tamper).
function taphish_backup_decrypt_stream(callable $read, callable $write, callable $decFn): bool
```

The `$read`/`$write` closures are backed by real file handles in the CLI and by
in-memory string buffers in tests — so the entire container format round-trips
offline with no filesystem.

## Data flow

**`backup_run.php`:**
1. CLI guard; parse `--keep=N` (default 7), `--dry-run`, `--out=DIR` (default
   `spear/uploads/backups`).
2. Bootstrap `config/db.php` (`$conn`, `$curr_db`); abort if no mysqli.
3. **Key gate (hard):** `secret_at_rest_get_key()===null` → exit 1 (never write an
   unencrypted backup).
4. Ensure backups dir exists; write the deny-all `.htaccess` if missing.
5. `--dry-run`: list tables + approximate row counts, print intended filename, exit 0
   without writing.
6. Open a temp `.sql` (`tempnam`); `SHOW TABLES`; per table: `SHOW CREATE TABLE` +
   streamed `SELECT *` (mysqli unbuffered/`use_result` so rows don't all load) →
   `taphish_backup_dump_table(..., $write=fwrite-to-temp)`.
7. gzip the temp `.sql` → temp `.gz` (`gzopen`/`gzwrite`, streamed).
8. `taphish_backup_encrypt_stream($readGz, $writeTapbak, 'secret_at_rest_encrypt'…)`
   into a temp `.tapbak`.
9. **Atomic publish:** `rename()` the temp `.tapbak` into the backups dir as
   `taphish_backup_filename($utcStamp)` only after full success (a crash leaves no
   half-backup).
10. Rotate: list `*.tapbak`, `taphish_backup_rotation_plan(...)`, `unlink` the losers.
11. Audit line (`logIt(..., 'cli')`); clean temps; exit 0 (3 on any failure).

**`backup_restore.php`:**
1. CLI guard; parse `--in=FILE` (required), `--out=FILE` (default `<in>.sql`),
   `--apply`, `--yes`.
2. Bootstrap + key gate.
3. `taphish_backup_decrypt_stream` from `--in` → gunzip → write `.sql` to `--out`.
4. If `--apply`: require `--yes`; then run the statements against `$conn` (this
   DROPs+CREATEs+INSERTs — destructive restore). Without `--yes`, refuse and tell the
   operator the decrypted `.sql` path so they can inspect/apply manually.
5. Audit; exit codes per convention.

## Security

- Backups dir gets a **deny-all `.htaccess`** (covers Apache 2.4 `Require all denied`
  and 2.2 `Deny from all`) — `spear/uploads/` is otherwise web-reachable.
- The container is encrypted with `secret.key`; the DB already stores PII/secrets as
  `enc1:` inside, so the dump is doubly protected at rest and protected if the file
  leaves the host.
- `secret.key` and `db.php` are **never** in the backup (DB-only dump; config dir not
  touched) — a backup must not carry its own decryption key.
- Restore `--apply` is gated behind explicit `--yes`.

## Error handling

| Condition | Behavior |
|---|---|
| At-rest key unavailable | Abort before writing; exit 1. |
| No DB connection | Abort; exit 1. |
| Temp file / dir not writable | Abort; exit 1; clean any temp. |
| A table dump or encrypt-chunk fails | Abort the whole run; delete temp; **no** partial `.tapbak`; exit 3. |
| Atomic rename fails | exit 3; temp cleaned. |
| Restore: bad magic / truncated / decrypt fail | exit 1; no `.sql` left behind. |
| Restore `--apply` without `--yes` | Refuse; print decrypted `.sql` path; exit 2. |

## Assumptions

- Columns are text/int/UTF-8 (the schema is). Values are emitted single-quoted +
  `real_escape_string`d; NULL as literal `NULL`. No binary/BLOB columns exist, so hex
  literals aren't needed. (Noted so a future BLOB column triggers a revisit.)
- `gzopen`/`ZipArchive`-class zlib functions are available (zlib is standard; the app
  already relies on openssl + ZipArchive).

## Testing (offline, fixed key + in-memory streams)

`tests/BackupHelperTest.php`:
- table header: `DROP TABLE IF EXISTS` + CREATE + trailing `;`.
- insert: 2 columns, a normal value, a value with `'`/`\`, and a NULL → exact string,
  NULL unquoted, others quoted+escaped (stub escaper = `addslashes`).
- `taphish_backup_dump_table`: header once + one INSERT per row; returns row count;
  empty rows → header only, count 0.
- filename: stamp → `taphish-backup-<stamp>.tapbak`.
- rotation: 10 files keep 7 → 3 oldest returned; keep ≥ count → `[]`; keep 0 → all.

`tests/BackupArchiveTest.php` (real `secret_at_rest_encrypt/decrypt`, fixed key,
`TAPHISH_BACKUP_CHUNK` shrunk via the param to force multiple frames):
- encrypt→decrypt round-trips a multi-chunk payload byte-exactly.
- output begins with `TAPBAK1\n`.
- empty payload → header only, decrypts to `''`.
- wrong key on decrypt → false (no partial output trusted).
- flipped byte in a frame → decrypt returns false.
- truncated container (cut mid-frame) → false.
