# Phase 3.50b — State-dir snapshot (combined backup)

**Status:** approved (delegated; deliver fully tested + deployed)
**Date:** 2026-06-04
**Builds on:** Phase 3.50 (`.tapbak` chunked-encrypted container, `backup_run`/`backup_restore`)

## Goal

Extend the encrypted backup to optionally capture the application **state dirs**
(cloned landing pages + uploaded files) in the **same** `.tapbak`, so one archive
restores the whole install. DB-only stays the default.

## State roots (archived under a `state/` prefix)

- `spear/sniperhost/cloned/`  → `state/cloned/…`
- `spear/uploads/attachments/` → `state/attachments/…`
- `spear/uploads/timages/`    → `state/timages/…`

Enumerating these three dirs specifically means `spear/uploads/backups/` is never
swept into a backup (no backup-of-backups recursion), and `spear/config/` (secret.key,
db.php) is never included.

## Container

When `--with-state` is set, the inner payload is a **ZIP** (`db.sql` + `state/…`)
instead of `gzip(sql)`. The ZIP is then chunked-encrypted by the existing
`taphish_backup_encrypt_stream` into the same `.tapbak`. `ZipArchive::addFile` streams
from disk and entry extraction via `getStream` streams out → memory stays bounded.
ZIP (not tar) because `ZipArchive` is already available and gives random-access restore.

## Restore format detection

`backup_restore.php` decrypts to a temp inner file, then **sniffs the first bytes**:
- `\x1f\x8b` → gzip → legacy DB-only path (write `.sql`, `--apply` applies). Unchanged.
- `PK\x03\x04` / `PK\x05\x06` → zip → extract `db.sql` (+ `--apply` applies) and the
  `state/…` entries.

## New pure helper `spear/manager/backup_state.php`

```php
// roots: ordered map archivePrefix => absoluteRootDir
// lister: fn(string $absDir): string[]  relative file paths (real: recursive iterator)
// returns: list of ['src'=>absFile,'dest'=>archivePath]
function taphish_backup_state_manifest(array $roots, callable $lister): array

// first bytes -> 'gzip' | 'zip' | 'unknown'
function taphish_backup_sniff_format(string $head): string

// map 'state/cloned/x.html' back to an absolute path under the matching root,
// rejecting zip-slip (any '..' segment, NUL, or escape past the root) -> null
function taphish_backup_state_restore_target(string $archivePath, array $roots): ?string
```

## Safety

- **Zip-slip guard:** every restored entry is validated by
  `taphish_backup_state_restore_target` (rejects `..`, NUL, escape) before any write.
- State copy-back to the live roots only happens under `--apply --yes` (same gate as
  the destructive DB apply). Default restore extracts to a staging dir for inspection.
- Memory bounded: stream into the zip, stream entries out, 1 MiB crypto frames.
