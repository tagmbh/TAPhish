# Phase 3.33 — Dim mode for sidebar + Home dashboard

## Purpose

Phase 3.32 brought the login screen and the 2FA settings card on to the
TAPhish operator-console design system. Every other surface still reads
as upstream SniperPhish / Material Admin: bright `#f4f6f9` body, default
sidebar tokens, untouched card styling. The discontinuity between the
front door and the inside of the panel breaks the brand promise.

Phase 3.33 closes that gap on the two surfaces an operator looks at most
often: the **left sidebar** (visible everywhere inside the panel) and
the **Home dashboard** (the first thing they see after login). Other
internal pages (campaign lists, mail templates, settings beyond the 2FA
card) keep the bright-mode default for now — they get their own phases.

## Aesthetic direction

Same as the login screen: refined operator-console. Dim navy backdrop,
restrained primary accents, distinctive typography pair (Bricolage
Grotesque display, IBM Plex Sans body, JetBrains Mono for status text
and tabular numbers).

## In scope

### Sidebar (`spear/z_menu.php` + brand.css rules)

- Background: `--t-bg-elevated` panel sitting on a `--t-border` rule.
- Brand block at the top: 32×32 primary tile with "TA" mark, wordmark
  "TAPhish" in display font, mono caption "OPERATOR CONSOLE" beneath.
- Section dividers — small uppercase mono labels ("Workspace", "Toolkit"
  …) that introduce groups of nav items. The current `z_menu.php` has
  no section structure; this PR introduces it via a thin markup change
  (one `<li class="sidebar-section">Workspace</li>` style row per group)
  rather than restructuring the navigation tree.
- Active item: `--t-primary-edge` left-border + `rgba(26,90,138,0.16)`
  tinted background. Inactive: `--t-text-mute`. Hover: `--t-text` with
  no background shift.
- Footer (bottom of the sidebar): mono row showing `v2.1` on the left
  and the cron-worker indicator on the right (green dot + "ready" when
  the existing `checkSniperPhishProcess` reports the worker is up;
  amber dot + "stopped" otherwise). Wires into the existing notifier
  rather than introducing a new poll.

### Home dashboard (`spear/Home.php` + brand.css rules)

Replace the current Home content with a four-card metric strip + a
recent-activity feed. The campaign / open / click metrics already exist
in `home_manager.php`; the cron-worker tile reads the existing process
state. The activity feed is the only piece that needs new data: it
shows the latest entries from `tb_logs` (or whatever the existing
`logIt()` writes to), formatted as `time · kind · message · status`.

- Card surface: `--t-bg-elevated` with `--t-border` outline, 8px radius.
- Card labels: mono uppercase 9px with `0.14em` tracking.
- Card numbers: Display font, 32px, weight 600.
- Trend line: mono 10px with `--t-success` / `--t-warn` / `--t-danger`
  depending on direction.
- Activity rows: mono, monospaced columns, dotted `--t-border` between
  rows. Status labels colored by severity.

### Topbar

Slim 52px bar above the content area, dark like the body. Display-font
page title on the left, mono user-chip on the right (existing user
identity, no new surface).

## Out of scope (explicit non-goals)

- Campaign list, template editor, recipient list, the rest of Settings —
  Phase 3.34+.
- Third-party widget restyling (DataTables, Summernote, Select2,
  toastr) — they still appear in the rest of the panel which stays
  bright-mode, so they keep their default theming until Phase 3.34
  ports the rest.
- Restructuring the sidebar navigation tree — only cosmetic dividers
  added, no link reordering.
- A new audit-log persistence layer. The activity feed reads from
  existing `tb_logs` only. Phase 3.34 / 3.35 will address audit-log
  proper.

## Token additions

`spear/css/brand.css` already exports the color, type, and spacing
tokens introduced in Phase 3.32. No new tokens. The only additions are
selector blocks targeting:

- `.left-sidebar`, `.sidebar-nav`, `.sidebar-link`, `.sidebar-link.active`
- `.sidebar-section` (new utility class introduced in `z_menu.php`)
- `#main-wrapper`, `.page-wrapper`, `.page-breadcrumb`
- `body.dim-home` (page-scoped opt-in — applied via PHP body class on
  Home only, so other internal pages don't accidentally flip)
- Metric-card classes (`.t-metric`, `.t-metric-label`, `.t-metric-num`,
  `.t-metric-trend` — new utility classes inside Home markup)
- Activity-feed classes (`.t-activity`, `.t-activity-row`, etc.)

The `body.dim-home` gate is the safety mechanism: it keeps the rest
of the panel on the bright default so changing the Home dashboard
can't accidentally break the campaign editor or the template editor.

## Architecture

CSS-only changes plus targeted PHP markup edits:

- `spear/css/brand.css` — extended with `.left-sidebar`, `body.dim-home`,
  and Home metric/activity blocks.
- `spear/z_menu.php` — sidebar section labels, brand block, footer.
  Existing nav links unchanged. No PHP behavior change.
- `spear/Home.php` — `<body class="... dim-home">` opt-in, replace the
  current cards with the new metric strip + activity feed. The actual
  numbers come from the existing `home_manager.php` endpoint which is
  unchanged.

No new database tables, no new schema migration. One new read-only
dispatcher action (`get_recent_log_entries` on the existing
`home_manager.php`) for the activity feed — same dispatcher style and
auth gate as the existing actions in that file.

## Data flow

```
Home.php
  └─ JS calls existing manager/home_manager.php
       ├─ get_dashboard_metrics  (campaigns, open%, click%, cron state)
       └─ get_recent_log_entries (new endpoint — reads tb_logs, returns
                                  the last N rows formatted for display)
```

The `get_recent_log_entries` action is the only new server-side surface.
It is read-only, no parameters, returns a list of `{time, kind, message,
severity}` objects. The "kind" tag is derived from the existing logIt
message prefix (`Account login`, `Campaign sent`, …) via a small
classifier in PHP. No new column, no schema change.

## Error handling

- If `tb_logs` is empty (fresh install): show a quiet empty state
  ("No activity yet — start a campaign or change a setting") instead
  of an empty box.
- If the dashboard-metrics endpoint fails: the four cards render with
  "—" instead of numbers, no toast (uptime monitors will surface this
  via /status; the operator doesn't need a popup).
- If the cron-worker check fails: the footer indicator goes amber,
  not green, with "unknown" as the status text. Doesn't block the
  rest of the UI.

## Testing

- **Unit**: a pure helper that maps a `logIt()` message prefix to a
  4-letter kind tag (`Campaign sent` → `CAMP`, `Account login` → `AUTH`,
  …). Tested against a fixed table of fixtures. No DB, no session.
- **Visual smoke**: deploy → `curl https://ptbe.autodiscover.li/spear/
  Home` → assert that the response body contains `body class="...dim-
  home"` and the `.t-metric` class (proves the styles loaded and the
  markup made it through).
- **Manual**: after deploy, log in, look at sidebar + dashboard. Walk
  to one bright-mode page (Settings) and confirm it still renders as
  expected.

## Accessibility

- All text on `--t-bg-elevated` meets WCAG AA contrast: `--t-text`
  (#e6ecf2) on #131e2c is 13.4:1; `--t-text-mute` (#8a96a7) is 5.8:1.
- Focus-visible outline ring inherited from Phase 3.32.
- `prefers-reduced-motion` respected: card hover transitions and any
  reveal animation gated.

## Rollback

Each block is additive CSS. A revert of the brand.css extension and
the two PHP files (z_menu.php, Home.php) restores the upstream bright
theme on those surfaces. The rest of the panel was never touched.
