# Phase 3.34 — Extend dim mode to the Settings pages

## Purpose

Phase 3.33 brought the operator-console dim treatment to the Home dashboard and shared topbar + sidebar. That left the two Settings pages (`SettingsUser.php`, `SettingsGeneral.php`) on the bright Bootstrap theme, so navigating from Home → Settings is a jarring brightness swing. Phase 3.34 closes that gap.

## Aesthetic direction

Same as 3.33. No new tokens.

## Scope-defining rename

The `.dim-home` body class introduced in 3.33 was misnamed — only the metric strip + activity feed are truly Home-specific. The topbar + sidebar + page-background rules in `brand.css` apply to ANY page that wants the operator-console look. Renaming to `.dim-panel` makes that contract explicit and lets multiple pages opt in without sharing the literal name "home".

Rename `.dim-home` → `.dim-panel` everywhere in `spear/css/brand.css` and update the body class on `Home.php`. The Home-specific selectors (`.dim-panel .t-dashboard`, `.dim-panel .t-metric*`, `.dim-panel .t-activity*`) keep working unchanged — they're already qualified by the surrounding `.t-*` class.

## In scope

### Body class flip on SettingsUser.php

Add `dim-panel` to the existing `<body>` class list (currently bare `<body>`). That alone gives the page the dim background, dim topbar, dim sidebar, brand-blue active sidebar item, and the dim version of the page-breadcrumb / page-title typography. No other markup change needed for those wins.

### Body class flip on SettingsGeneral.php

Same: append `dim-panel` to the body class. Inherits everything.

### Card surface CSS

Settings pages render their content as Bootstrap `.card` / `.card-body` panels. Today these are white-on-`#f4f6f9`. Add three rules to `brand.css`:

- `.dim-panel .card` → `--t-bg-elevated` bg, `--t-border` border, no `box-shadow`
- `.dim-panel .card-body` → text color `--t-text`
- `.dim-panel .card-title`, `.dim-panel hr` → already covered by the Phase 3.32 typography block + a single border-color override for `<hr>` in dim mode

### Form-input surface CSS

The 2FA enrollment, account-edit, password-change forms use Bootstrap `.form-control` inputs. In dim mode they need:

- `.dim-panel .form-control` → transparent bg with `--t-bg` underlay, `--t-border` border, `--t-text` color, `--t-text-dim` placeholder
- `.dim-panel .form-control:focus` → `--t-primary-edge` border + glow (reuse the existing `--t-glow` token)
- `.dim-panel .input-group-text` → muted bg, `--t-text-mute` text

### Modal CSS

The 2FA enrollment modal, the recovery-codes display modal, and the disable-2FA modal currently render with Bootstrap's default white `.modal-content`. Three rules:

- `.dim-panel .modal-content` → `--t-bg-elevated`, `--t-border`, `--t-text`
- `.dim-panel .modal-header`, `.dim-panel .modal-footer` → matching `--t-border` divider
- `.dim-panel .close` → `--t-text-mute` color so it's visible against the dark surface

### Table surface CSS (SettingsUser admin-account table)

The "TAPhish Accounts" table on SettingsUser.php is a plain `.table.table-striped.table-bordered`. Rules:

- `.dim-panel .table` → `--t-text` text
- `.dim-panel .table-striped > tbody > tr:nth-of-type(odd)` → subtle stripe `rgba(255,255,255,0.02)`
- `.dim-panel .table-bordered` → `--t-border` cell borders

## Out of scope (explicit)

- DataTables JS plugin (separately themed; covered in Phase 3.36).
- The campaign list, template editor, recipient lists (Phase 3.36).
- Toastr notification skinning (covered by Phase 3.36).
- Sidebar nav-tree restructure (still no).

## Architecture

Pure CSS + two markup edits:

- `spear/css/brand.css` — global rename `.dim-home` → `.dim-panel` (55 occurrences); append a new `.dim-panel`-scoped block covering `.card`, `.form-control`, `.input-group`, `.modal-*`, `.table*`.
- `spear/Home.php` — change `<body class="dim-home">` → `<body class="dim-panel">`.
- `spear/SettingsUser.php` — `<body>` → `<body class="dim-panel">`.
- `spear/SettingsGeneral.php` — same.

No PHP behavior change. No new DB schema. No new endpoints. No new JS.

## Testing

- **Unit**: nothing to add. The pure-helper layer is unchanged. Suite must remain at 293/718 after the rename + appends.
- **PHP lint** on the three modified PHP files.
- **Visual smoke after deploy**: `curl https://ptbe.autodiscover.li/spear/SettingsUser` body should contain `dim-panel`. Same for `SettingsGeneral`. Same for `Home` (still `dim-panel`, not `dim-home` anymore).
- **Manual**: log in, walk Home → Settings → 2FA modal → back to Home. Visual continuity should hold throughout.

## Accessibility

Inherited from Phase 3.32 (focus-visible ring, `prefers-reduced-motion` block already cover everything new). Contrast on the new surfaces:

- `--t-text` on `--t-bg-elevated`: 13.4:1 ✓ AAA
- `--t-text-mute` on `--t-bg-elevated`: 5.8:1 ✓ AA large + body
- Modal close `×` on `--t-bg-elevated` via `--t-text-mute`: same 5.8:1 ✓

## Rollback

Single revert of the merge commit restores the bright Settings + Home theme. The `.dim-home` → `.dim-panel` rename is a non-breaking refactor (no other code references the class name outside `brand.css` + `Home.php`).
