# Phase 3.50c — Off-host backup push (S3 + WebDAV)

**Status:** approved (delegated; deliver fully tested + deployed)
**Date:** 2026-06-04
**Builds on:** Phase 3.50 (`backup_run.php`), Phase 3.38 (at-rest envelope), the
`tb_store` encrypted-config + injectable-curl patterns (capture_alerting / telegram).

## Goal

After `backup_run.php` writes a `.tapbak`, optionally **push it off-host** to an
operator-configured **S3** (or S3-compatible) bucket or **WebDAV** target, for
disaster recovery. Opt-in (`--push`); the local backup is authoritative and a push
failure never invalidates it.

## Scope (v1, locked)

- **In:** WebDAV (HTTP PUT + Basic auth) and S3 (HTTP PUT + AWS SigV4), config stored
  encrypted in `tb_store`, set via a small CLI, triggered by `backup_run --push`.
- **CLI-only** (consistent with the whole backup system). A SettingsGeneral UI card is
  a deliberate follow-up — this phase stays in the verifiable CLI domain.
- **Deferred:** UI card, multi-destination fan-out, server-side encryption headers,
  retry/backoff queues.

### Boundaries

- **Pure layer** builds request descriptors `{method, url, headers}` from config +
  (for S3) a precomputed `payloadSha256` + `amzDate`. No I/O, no clock, no file reads
  → fully deterministic and unit-testable.
- **Transport** (`taphish_push_send($request, $filePath, ?callable $http)`) streams the
  file via curl `PUT` (`CURLOPT_PUT` + `CURLOPT_INFILE` → bounded memory). The `$http`
  seam is injected in tests; the default uses real curl.
- **CLI** computes `payloadSha256 = hash_file('sha256', …)` (streams from disk) and
  `amzDate = gmdate("Ymd\\THis\\Z")`, then calls the pure builder + transport.

## Component contracts

```php
// Validate + normalize a destination config. type ∈ {webdav, s3}.
function taphish_push_config_validate(array $cfg): array  // {ok:bool, errors:string[], cfg:array}
function taphish_push_config_serialize(array $cfg): string // JSON for tb_store
function taphish_push_config_deserialize(?string $json): ?array
function taphish_push_config_mask(array $cfg): array       // redact secret/password for display

// WebDAV: PUT <base>/<name> with Basic auth.
function taphish_push_webdav_request(array $cfg, string $remoteName): array // {method,url,headers}

// AWS Signature V4 (verified against the AWS "get-vanilla" test vector).
function taphish_sigv4_signing_key(string $secret, string $dateStamp, string $region, string $service): string // raw HMAC chain
function taphish_sigv4_authorization(array $o): string  // the full "AWS4-HMAC-SHA256 Credential=…,SignedHeaders=…,Signature=…" header
//   o keys: accessKey, secret, region, service, method, host, canonicalUri,
//           query(string), headers(map, lowercased), signedHeaders(string),
//           payloadSha256, amzDate, dateStamp
function taphish_push_s3_request(array $cfg, string $remoteName, string $payloadSha256, string $amzDate): array

// Transport. $http: fn(array $request, string $filePath): {ok,status,error}
function taphish_push_default_http(array $request, string $filePath): array
function taphish_push_send(array $request, string $filePath, ?callable $http = null): array // {ok,status,error}
```

### Config shapes (stored as sealed JSON in `tb_store` type='backup_push' name='config')

- WebDAV: `{type:'webdav', url:'https://host/backups/', user:'…', pass:'…'}`
- S3: `{type:'s3', bucket:'…', region:'…', access_key:'…', secret_key:'…', endpoint?:'…', path_style?:bool}`
  - Default host `<bucket>.s3.<region>.amazonaws.com` (virtual-hosted); `endpoint` +
    `path_style` support S3-compatible providers (Wasabi, B2, MinIO).

### S3 PUT signing

Signed headers: `host;x-amz-content-sha256;x-amz-date`. `x-amz-content-sha256` is the
hex SHA-256 of the file body (streamed via `hash_file`). Object is private (no ACL
header). The full SigV4 chain (canonical request → string-to-sign → signing key →
signature) is verified byte-for-byte against the AWS get-vanilla vector
(`AKIDEXAMPLE` / `wJalrXUtnFEMI/K7MDENG+bPxRfiCYEXAMPLEKEY`, 20150830, us-east-1,
service `service` → signature `5fa00fa31553b73ebf1942676e86291e8372ff2a2260956d9b8aae1d763fbf31`).

## CLI

`backup_push_config.php`:
```
--type=webdav --url=… --user=… --pass=…
--type=s3 --bucket=… --region=… --access-key=… --secret-key=… [--endpoint=…] [--path-style]
--show   (masked)   |   --clear
```
Validates, seals via `secret_at_rest_encrypt`, upserts `tb_store`. CLI-only guard; key
gate (won't store a plaintext secret if no at-rest key).

`backup_run.php --push`: after the local `.tapbak` is published + rotated, read +
decrypt the config; if present, `hash_file` the `.tapbak`, build the request, PUT it,
and report `pushed → <dest>` or a warning. **Exit 4** if `--push` was requested and the
push failed (local backup intact); plain success otherwise. Audit-logged either way.

## Security

- Secrets (S3 secret key / WebDAV password) sealed at rest in `tb_store`; `--show`
  masks them; never logged.
- TLS verification on by default (`CURLOPT_SSL_VERIFYPEER`).
- Push failure is non-fatal to the backup (the encrypted local copy already exists).

## Testing

`tests/BackupPushTest.php` (offline):
- config validate: webdav needs url/user/pass; s3 needs bucket/region/keys; bad type → error.
- serialize/deserialize round-trip; mask redacts secret/pass.
- WebDAV request: URL join + `Authorization: Basic …`.
- **SigV4 get-vanilla vector**: `taphish_sigv4_authorization` reproduces AWS's published signature exactly.
- S3 request: signed headers present; `Authorization: AWS4-HMAC-SHA256 …`; correct host (virtual-hosted + path-style).
- `taphish_push_send` with a fake `$http`: ok on 2xx, not-ok on 5xx, error surfaced; never reads the network.

**Integration harness (throwaway):** start a local `php -S` PUT receiver, push a real
file through `taphish_push_default_http` (real curl), assert the server stored it
**byte-identical** with a 2xx — proving the actual transport. (Real S3 is operator-verified;
SigV4 is vector-proven.)
