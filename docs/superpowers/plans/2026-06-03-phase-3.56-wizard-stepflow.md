# Phase 3.56 — QuickStart wizard: resumable step-by-step flow

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn the QuickStart wizard from a single long scroll into a true step-by-step flow with Next/Back navigation (one step visible at a time), and make an unfinished engagement **resumable** — reopen it later and continue from the step you left off. Fixes the operator-reported bug "if I stopped the wizard I can't continue afterwards."

**Architecture:** The wizard already renders all 7 steps in the DOM (`step1_wrap` … `step7_wrap`); they're just all visible. This phase adds (1) a client-side step controller that shows one wrap at a time with Next/Back + the existing animated stepper, and (2) server-side persistence of wizard progress on the engagement row so reopening `QuickStart?engagement_id=N` restores the current step + entered values. No rewrite of the step logic — it's a navigation + persistence layer on top.

**Tech Stack:** PHP 8.1+ (mysqli), jQuery, existing engagement schema + dispatcher.

---

## Current state (what exists)

- `spear/QuickStart.php` renders 7 step wraps, all shown. An animated stepper (`#t_stepper`) already exists from Phase 3.44.
- `spear/js/quick_start.js` has `setStepperState(n)` (highlights step n) and per-step handlers (`runOsint`, `runDkimGen`, `runRecipientPreview`, `runPreflight`, `runLaunch`).
- Step 1 saves the engagement (`save_engagement`) and returns a slug + id.
- Steps 2–7 currently just `show()` unconditionally on page load.

## Target behavior

1. **One step at a time.** Only the active step wrap is visible. Next/Back buttons move between them; the stepper reflects the active step and lets you click a completed step to jump back.
2. **Resumable.** After Step 1 saves, the engagement has an id. Each subsequent step-advance persists `wizard_step` (and a small `wizard_state` JSON of entered values: target domain, dkim selector, chosen pretext/landing, etc.) on the engagement. Reopening `QuickStart?engagement_id=N` loads that state and jumps to `wizard_step`.
3. **"Continue" entry points.** The recent-engagements list on QuickStart + EngagementView show a "Continue setup" link for engagements whose `wizard_step < 7` and status is `draft`.

## Schema change

Idempotent boot-time migration (mirrors Phase 3.45a/b), in `engagement.php`:

```sql
ALTER TABLE tb_core_engagement ADD COLUMN wizard_step  TINYINT NOT NULL DEFAULT 1;
ALTER TABLE tb_core_engagement ADD COLUMN wizard_state MEDIUMTEXT NULL;
```

`wizard_state` holds a small JSON blob of non-sensitive wizard inputs (target domain, dkim selector, chosen landing slug, chosen pretext id). NO secrets (DKIM private key is shown once and never stored; recipient PII stays in its encrypted table).

## Step controller contract (`wizard_stepflow.js`)

```
state = { step: 1..7, max_reached: 1..7 }
showStep(n):   hide all .step-wrap, show #step{n}_wrap, setStepperState(n)
next():        validate current step can advance (e.g. step1 must be saved),
               persist progress, showStep(step+1)
back():        showStep(step-1)   (no persist needed)
restore():     read #wizard_resume_step; if >1, showStep(that)
```

Advancing past Step 1 requires the engagement id (from the save response). Steps 2–7 are non-blocking — the operator can advance even if they skipped an optional lane, but the stepper marks which were completed.

Persist call: `wizard_save_progress { engagement_id, step, state }` fired on every `next()` and on `runLaunch` success (step 7 → mark complete).

## Open questions (with recommendations)
1. **Persist cadence.** Recommendation: persist on Next (not on every keystroke) — simplest, good enough; the operator loses at most the current unsaved step's inputs.
2. **What counts as "done".** Recommendation: `wizard_step = 7` after a successful launch; the Continue link disappears once status leaves `draft`.
3. **Skipped optional steps.** Recommendation: allow advancing; mark completed steps in the stepper but don't block on optional lanes (OSINT, landing pick).
